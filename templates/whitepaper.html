1. Network Purpose

Bitmini is built as a self-custody digital value network for wallet onboarding, peer-to-peer transfers, validator participation, and governance without requiring users to depend on a public chain such as Ethereum, Solana, or a centralized exchange wallet. The network’s purpose is to provide a clean user experience while preserving trust, transparency, and complete control over account ownership.

2. Token Model

The native asset is BMINI and the platform enforces a hard maximum supply of 21 million tokens. A fixed genesis reserve of 1 million coins remains locked to protect ecosystem stability, preserve treasury runway, and keep the system from over-issuing supply through uncontrolled validation rewards. The remaining supply is governed by policy checks, wallet activity, and referral-driven ecosystem growth, ensuring that every minted unit is traceable and bounded by explicit operational rules.

3. Consensus

Bitmini supports mobile-friendly validation modes including Proof of Stake, Delegated Proof of Stake, and Proof of Authority. These modes reduce the energy burden of traditional mining while allowing validator selection, proposer rotation, and reward allocation to remain open and auditable. The system prefers low-friction validation over hardware-heavy participation, which makes it more accessible for everyday users and smaller operators.

  • PoS: stake-based validation with low energy use and direct participation rewards
  • DPoS: delegation model that lets mobile users back trusted validators without running full infrastructure
  • PoA: authority-based mode for stable throughput during controlled network bootstrap stages

4. Security Layer

  • Password or seed-phrase based wallet access with encrypted secret storage
  • Session-token authorization required for all write operations
  • Wallet ownership verification on every sensitive request
  • Unique @username handles and identity-derived wallet IDs at registration
  • Self-send blocking, duplicate-payment detection, and protected locked balances
  • Slashing, epoch control, and validator monitoring for stable network behavior

5. Growth System

Referral mechanics are built to encourage real user adoption without overstimulating the supply model. Wallets can invite friends to join the network, receive referral-based rewards, and unlock growth incentives through a progressive reward curve. Invite flow is not blocked after a small count; instead, reward multipliers taper as monthly referral events increase. This preserves open growth while preventing reward systems from overwhelming the token economy.

In parallel, users can earn through controlled ad-view incentives and validator participation. The ad pathway uses per-wallet daily limits to reduce abuse, while consensus rewards follow network policy and halving discipline.

Wallet Creation

Users create a wallet by providing their identity profile, unique username handle, email, and password. These inputs generate a wallet address and wallet unique ID that make each account distinct while still keeping onboarding simple.

The workflow is optimized for mobile devices so new users can register, back up, and start transacting from a phone without navigating complex desktop-first wallet tooling.

Authorization Model

Access is protected by session-bound tokens and ownership checks. Even when a wallet address is known, no write action is allowed unless the active session matches the correct wallet. This blocks accidental or malicious cross-wallet activity.

Operational Safety

Locked-balance enforcement, duplicate transaction detection, and validator slash events help maintain trust in the ledger. These control points ensure that transaction validity remains tied to wallet state and protocol policy rather than user intent alone.

6. Governance and Validator Rotation

Governance is centered on validator selection, mining or validation order, epoch transitions, and protocol-grade safety checks. A selected validator set is rotated according to the active epoch, while slash events and validator health are monitored to protect network reliability. This creates a disciplined operating environment for a custom chain without heavy centralization.

7. Product Engineering Principles

Bitmini is designed for practical product deployment: it balances onboarding simplicity, wallet security, transaction trust, network visibility, and protocol governance. The system is structured for a web app, mobile wallet interface, and sovereign network runtime without needing to depend on external proof-of-work infrastructure, centralized custody, or third-party chain ecosystems.

8. Roadmap and Implementation Focus

  • Secure wallet registration and encrypted storage for identity-backed accounts
  • Session-based wallet authorization and transaction validation for all sensitive actions
  • Referral incentives and capped reward windows aligned to supply policy
  • Validator rotation, slashing controls, and epoch monitoring for chain health
  • Custom sovereign node integration for wallet and ledger visibility without external validator infrastructure
  • Continued refinement of wallet UX, governance reporting, and on-chain reporting for production readiness
